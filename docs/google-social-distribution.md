# Google social distribution (experimental)
Independent PR; no production activation. Reuses Google web OAuth client and the registered callback /api/reputation/google/callback, with separate state/PKCE and admin-only panel /admin/social. No refresh tokens in browser, logs, repo or public Sanity. Each brand/provider binding is stored in a separate encrypted private Blob file; existing CRM and reputation sessions are not replaced. Existing binding cannot be changed to another target by reauthorization.
Requirements: existing Google OAuth credentials, CRM admin allowlist and private BLOB_READ_WRITE_TOKEN; enable Google Business Profile account management/business information/My Business APIs and YouTube Data API v3 for the existing project, configure OAuth consent/scopes and ensure production offline authorization. GBP identity requires a unique location with the brand website domain. YouTube identity requires a unique authenticated channel with the exact normalized brand name. Mismatch blocks the connection; no guessed destination. Owner authorizes four connections in the admin panel after reviewed deploy.
Crosspost runs only in production, from existing posts confirmed on Meta, with same-day selection, explicit SOCIAL_GOOGLE_PUBLISH_SINCE (UTC ISO date), and SOCIAL_GBP_AUTOPUBLISH_ENABLED=true. Default off. One local post per brand/day; image cover and adapted caption, CTA points to own site. Persistent source/day locks prevent automatic retries on ambiguous submission. A readback state LIVE is required for published; submitted or verification_required must be reconciled. No historical backfill.
YouTube: both accounts can connect; initial transport is only for approved Velo Sophia MP4s already published on Meta and validated by the existing asset/hash/approval gates. SOCIAL_YOUTUBE_UPLOAD_ENABLED=true opt-in; private upload by default; SOCIAL_YOUTUBE_PUBLIC_ENABLED=true requires separate explicit release after real test. The upload uses the exact reviewed bytes. No automatic public retry or automatic promotion of private test videos. Long videos and EYAGENCIA video source wiring still pending.
YouTube Posts: official API currently restricted to pilot-approved projects; no public upload implementation or broader scope until access is confirmed. Assisted route only. TikTok: direct API policy excludes an internal self-account posting utility; use a compliant publishing provider or approved creator workflow, still pending. No extra provider subscription authorized.
Before activation: confirm build, typecheck, OAuth callback security and private storage, four account identities, permissions, media quality, real read-only API checks, provider statuses and non-public video upload. Verify production Vercel env metadata without exposing secrets. Do not merge with production before review.
