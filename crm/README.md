# CRM privado EYAGENCIA

Rota /admin. Login Google OAuth por redirecionamento, com PKCE, state e sessão HttpOnly assinada; API /api/admin/crm valida sessão e lista restrita de administradores server-side. Nenhum cliente real no repositório público. Os registros ficam em um Vercel Blob privado vinculado exclusivamente ao projeto, com inicialização idempotente via variável sensível de produção e atualização condicional ETag. As regras Firestore anteriores não são utilizadas por esta versão.

Configuração: BLOB_READ_WRITE_TOKEN do store privado, EY_CRM_ADMIN_EMAILS e EY_CRM_INITIAL_DATA exclusivamente server-side, GOOGLE_GBP_CLIENT_ID e GOOGLE_GBP_CLIENT_SECRET existentes. O callback Google registrado é compartilhado somente no endereço, com state, escopo e cookies independentes do Perfil da Empresa. Não armazena tokens Google na sessão do CRM. Verificar acesso do administrador no consentimento OAuth. Testar acesso anônimo 401, conta Google não autorizada sem sessão, entrada da conta permitida, gravação/recarga e concorrência (409). Não registrar valores reais como recebidos sem comprovante. O cadastro inicial inclui referências de valores históricos e projetos pendentes, não equivale a receita confirmada. Cobrança/assinatura ainda são controles manuais.

Não imprimir variáveis nem payloads em logs. Não expor a base em JSON público, analytics ou HTML pré-renderizado. Não reutilizar tokens de outras aplicações. A base usa snapshot JSON com controle otimista, adequado à operação administrativa inicial; migrar para banco transacional se volume ou concorrência crescer.
